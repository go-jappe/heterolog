# Windows VM初回予備試験（2026-09-10）

## 範囲

QEMU/KVM上で既存`Win10_22H2_Japanese_x64.iso`のセットアップを起動し、インストール前
環境で試験exeを実行しました。`ver`の表示は`10.0.19041.2006`です。
通常のWindows 10/11をインストールした後の試験ではありません。

専用80 GiB仮想ディスクに新規2 GiB NTFS領域を作り、`T:`へ割り当てました。
`TEMP`と`TMP`は`T:\temp`に設定したため、RAM diskではなくこのNTFS領域で試験しました。
ホストのデータや`.env`はguestへ共有していません。

## 結果

以下はsubtestを別計上しない、最上位test単位の件数です。

| Package | PASS | FAIL | SKIP | exe終了code |
| --- | ---: | ---: | ---: | ---: |
| fsstore | 28 | 3 | 1 | 1 |
| appendlog | 54 | 14 | 0 | 1 |
| failurearchive | 20 | 2 | 0 | 1 |

全体終了codeは1です。全件成功ではありません。

### 製品処理で再現した同期失敗

`SyncParentDirectory`の`existing parent`試験で、以下のerrorを確認しました。

```text
SyncParentDirectory() error = sync parent directory ...: Access is denied.
```

圧縮file公開後のdirectory同期、圧縮sourceの削除待ち処理、checkpoint directory同期も
同様に失敗しています。Windowsのdirectory handleと同期方法の対応が必要です。
この作業では製品処理を修正していません。

### 試験側のWindows path表記

`%q`でerrorへ埋め込んだpathと、escape前のWindows pathを`Contains`で照合する試験が
あります。backslashのescapeによって一致せず、失敗しています。これは同期errorとは
別の試験側の問題です。この作業では既存testのassertionを変更していません。

### 試験環境のタイムゾーンデータ

Goやzoneinfoがない環境のため、`Asia/Tokyo`の読み込みが2件失敗しました。
この結果を確認した後、メディア作成scriptに`-tags=timetzdata`を追加しています。
その追加後のexeはWindows上ではまだ再実行していません。表は追加前の実測結果です。
次回用ISOはVM directoryの`fsstore-windows-tests-timetzdata.iso`に別名で保存しています。

## 生ログと再現用メディア

生ログと7つの結果fileは次のdirectoryへ回収済みです。

```text
/path/to/virtual-machines/heterolog-windows/results-winpe-20260910/results/
```

今回実行したISOは同じVM directoryの`fsstore-windows-tests.iso`です。
SHA-256:

```text
6e96c6a9938c38abc615dbc726870347f30327772879ddb20b3acf127dbf5a3e
```

結果取得用仮想USBへlogをcopyし、Windows自身の`wpeutil shutdown`で停止してから
host側へ回収しました。VM正常終了、QEMU終了、QMP/TPM socketの消滅を確認しています。

比較として、同じ3 packageをLinux上で`go test -race -count=1 -timeout=180s`により
実行し、すべて成功しました。Windows側の予備試験にはrace detectorを使用していません。

再利用用launcherの終了処理は、6つのmock scenarioを20回ずつ実行して成功しました。
最終版launcherでも、インストールISOなしで実QEMUを起動し、KVM・TPM・結果取得用USBの
接続を確認して終了しています。VMは現在停止中です。
